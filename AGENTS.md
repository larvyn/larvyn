# AGENTS.md

Larvyn is a desktop workbench for Laravel apps: Go + Wails 3 backend, React +
TypeScript frontend. This file is a map and a set of rules, not full docs; see
`README.md` for what the app does and `TASKS.md` for open work.

## Layout

| Path | What lives there |
| --- | --- |
| `main.go` | App start-up and Wails service registration (`application.NewService(...)`). |
| `agentapi*.go` | Local API used by agents: the `larvyn` CLI and the MCP tools (context, terminals, stack, artisan and tests, models and db, agents, locks, setup). |
| `cmd/larvyn` | The `larvyn` CLI binary. |
| `internal/<area>` | One package per area: `agents`, `stack`, `terminal` (PTYs), `proc` (processes), `git`, `laravel`, `project`, `store` (settings/state), `updater`, `api`, … |
| `internal/laravel/bridge.php` | Embedded (`//go:embed`) PHP script run inside the user's Laravel app for routes, models, Tinker, etc. |
| `frontend/src/views/*.tsx` | One file per screen (Overview, Agents, Terminals, Database…). |
| `frontend/src/components`, `lib` | Shared UI; `lib/store.ts` is the zustand store. |
| `frontend/src/styles/app.css` | All styling and color tokens. |
| `frontend/bindings` | Generated by Wails from the Go services. Never edit by hand. |
| `.github/workflows` | `test.yml` (CI), `release.yml` (builds and publishes on a version tag). |

Platform-specific Go code goes in `_windows.go` / `_other.go` pairs (see
`internal/proc`). Never build with `-tags server` (`server_mode_disabled.go`).

## Commands

- Build: `wails3 build` → `bin/larvyn` (`bin/larvyn.exe` on Windows). It also
  regenerates `frontend/bindings`, so run it after changing a service's
  exported methods or types.
- Dev mode: `task dev`.
- Before calling anything done, all of these must pass:
  ```sh
  go vet ./...
  go test -race ./...
  gofmt -l .                       # must print nothing
  (cd frontend && npx tsc --noEmit)
  ```
- `scripts/ci-local.sh` runs the CI workflow locally (Linux in Docker, macOS natively).

## Rules

- **Isolated home.** Run the app and tests with `LARVYN_HOME=<temp dir>` so the
  real settings are never touched. `LARVYN_VIEW=<view>` opens straight into a
  view. Go tests that need a home set it in `main_test.go`.
- **Real Laravel projects are read-only.** Use them to look, never to write,
  migrate or install. Make a throwaway project for anything that changes files.
- **Processes go through `internal/proc`.** Use `proc.Run`, `proc.Artisan`,
  `proc.Git`, `proc.KillTree`… instead of raw `exec.Command`, so windows stay
  hidden on Windows and children die with their parent.
- **Bindings can return `null`.** Go slices and maps arrive as `null` when
  empty. Pass plain objects in, and guard lists coming out:
  ```ts
  const worktrees = (await GitService.Worktrees(root)) ?? []
  ```
- **zustand selectors must return stable values.** A selector that builds a new
  `[]` or `{}` on every call makes React loop forever.
  ```ts
  // bad: new array on every render
  const tabs = useStore((s) => s.tabs.filter((t) => t.project === id))
  // good: select the stable value, derive outside
  const all = useStore((s) => s.tabs)
  const tabs = useMemo(() => all.filter((t) => t.project === id), [all, id])
  // good: fallback that is a shared constant
  const EMPTY: Tab[] = []
  const list = useStore((s) => s.byProject[id] ?? EMPTY)
  ```
- **Think cross-platform.** Terminals use ConPTY on Windows and a PTY elsewhere;
  paths, shells and process trees differ. Touching `proc` or `terminal` means
  checking both the `_windows.go` and `_other.go` sides.
- **Commits.** Conventional commits, lowercase, one line
  (`feat(agents): …`, `fix(terminal): …`, `docs: …`).
